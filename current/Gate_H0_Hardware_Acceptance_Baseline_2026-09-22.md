- Node A / Node B 的职责边界；

## 3. Gate H0 的目的和边界

Gate H0 只回答以下问题：

1. 实际收到了什么；
2. 数量、型号、芯片、板卡版本和接口标识是否明确；
3. 是否存在缺件、错件、损伤、弯针、虚焊或不明跳线状态；
4. 无源器件基本阻值是否有记录；
5. 12 V 适配器的铭牌、空载输出和极性是否明确；
6. 是否具备进入 Gate H1 单块 NUCLEO USB Bring-up 的条件。

Gate H0 不验证：

- 固件是否能下载或运行；
- ST-LINK、虚拟串口或目标 MCU 是否能被软件连接；
- CAN 双向通信；
- 风扇 PWM、Tach、INA260、NTC 温度换算；
- FreeRTOS 调度、IPC、Fault、Fallback 或 Recovery；
- 完整 12 V 功率回路和 Thermal Plant。

这些内容分别属于 H1 及后续 Gate。不得用 H0 的照片或万用表读数替代后续运行证据。

## 4. 状态定义

| 状态 | 定义 | 处理 |
|---|---|---|
| PASS | 实物身份、数量、接口和要求的证据均明确，未发现阻止下一阶段的问题 | 可计入 H0 完成项 |
| CONDITIONAL PASS | Gate 层面仍有开放偏差，但偏差与下一 Gate 的最小目标可通过明确物理隔离解耦 | 记录偏差、隔离边界和最迟关闭点；只授权写明的最小范围 |
| HOLD | 信息不明确、规格不一致、针脚/极性不清、证据不足或需要数据手册复核 | 隔离该物料，不上电、不接线 |
| FAIL | 已确认错件、损坏、极性错误、输出异常或不满足基线 | 停止使用，记录并安排退换/替代评审 |
| N/A | 经本文件或上游基线确认该检查对该物料不适用 | 写明理由，不能留空代替 N/A |
| NOT CHECKED | 尚未执行 | Gate H0 关闭时不得残留关键 NOT CHECKED 项 |

一件关键物料出现 HOLD 或 FAIL，不允许通过“先接起来看看”消除不确定性。应先补证据、查资料或更换物料。若该物料能被下一 Gate 完全排除，可在记录隔离边界后作 Gate 层面的 CONDITIONAL PASS，但不得把该物料本身改写为已验证。

## 5. Gate H0 安全红线

### 5.1 H0 第一步的安全状态

- 12 V 适配器不接市电；
- 两块 NUCLEO 不接 USB；
- 所有模块互相分离；
- Heater、Fan、INA260、CAN Pal、NTC 均不与 MCU 连接；
- 桌面干燥、绝缘、无散落金属；
- 不佩戴可能造成短路的金属物接触裸露端子；
- 先释放人体静电，再接触开发板和模块边缘。

### 5.2 H0 全程禁止事项

- 不搭建完整 12 V 风扇或 Heater 功率回路；
- 不把 12 V 接入 NUCLEO 的 3.3 V、5 V 或 GPIO；
- 不通过面包板、细杜邦线承载 Heater 电流；
- 不启用 INA260 ALERT；
- 不连接完整双节点 CAN 网络；
- 不同时接入 CAN、风扇、传感器和 RTOS 业务固件；
- 不用真实短路、危险堵转、过压或大电流制造 Fault；
- 不剪 P8 原装线，不使用 PST 串联接口参与初始验证；
- 不根据线色、商品图片或个人经验猜测针脚；
- 不在带电对象上使用电阻档、通断档或二极管档。

### 5.3 万用表使用要求

- 黑表笔插 `COM`；
- 测电阻时红表笔插 `VΩ`；
- 测适配器电压时红表笔仍插 `VΩ`，档位设为直流电压；
- 本阶段不把表笔插入 `A` 或 `mA` 电流插孔；
- 每次改变档位前确认被测对象是否带电；
- 测电阻前确认元件与所有电源、模块和电容性电路隔离；
- 不用蜂鸣器响声代替阻值、极性或绝缘结论。

## 7. 标识和证据命名规则

### 7.1 实物 ID

先按物理身份编号，不要提前绑定软件角色：

- `NUCLEO-01`、`NUCLEO-02`；
- `CANPAL-01`、`CANPAL-02`；
- `FAN-01`；
- `INA260-01`；
- `NTC-01`；
- `R10K-01`、`R4K7-01`；
- `HEATER-01`、`HEATSINK-01`；
- `PSU12V-01`；
- 其他辅材按类型连续编号。

两块 NUCLEO 在 H1 分别验证前，不永久指定为 Node A 或 Node B。否则一旦板卡互换，照片、日志和故障定位会失去可追溯性。

### 7.2 照片命名

推荐格式：

`H0_<实物ID>_<视图>_<YYYYMMDD>_<序号>.jpg`

视图建议使用：

- `overview`：全体物料总览；
- `front`：正面；
- `back`：背面；
- `marking`：型号/芯片丝印；
- `connector`：接口及针脚标识；
- `jumper`：跳线、焊桥、DIP 或终端状态；
- `damage`：损伤或异常细节；
- `measurement`：必要的仪表读数与被测对象同框照片。

同型号的两块板必须分别拍摄，不能用其中一块代表另一块。照片应能同时看清实物 ID 标签和被核对的标识。

## 9. 执行流程

必须按 H0-01 至 H0-07 顺序执行。任何 STOP 条件出现时，停止该物料的后续步骤，但可以继续清点其他保持隔离的物料。

### H0-01 建立全断电工作状态

操作：

1. 拔除 12 V 适配器市电输入；
2. 拔除两块 NUCLEO 的 USB；
3. 拆除所有临时连接；
4. 将物料分类摆放且互不接触；
5. 放置实物 ID 标签；
6. 拍摄一张全体物料总览照。

证据：

- 总览照片编号：`H0_ALL_overview_20260923_01.jpg`；
- 执行日期/时间：`2026-09-23（具体时间未记录）`；
- 执行人：`项目执行人已完成现场测试，姓名/签名待补`。

通过条件：所有物料可独立识别，现场无带电连接和复杂线束。

STOP 条件：无法确认适配器是否断电、桌面潮湿、存在裸露带电端子或金属杂物。

### H0-03 关键硬件身份核对

- PCB 正面型号包含 `NUCLEO-F103RB`；

- 所有出厂跳线、焊桥状态逐块拍照记录，H0 不随意改动；

- 不因一块板外观正常而外推另一块也正常。

判定：型号、MCU 或板版本无法确认时标记 HOLD；明显错件或损伤标记 FAIL。

#### H0-03B CAN Pal ×2（两块正反面/针脚/终端照片已补；实体芯片顶标待补）

逐块核对：

- 模块产品标识和版本；
- 收发器芯片丝印是否为预期的 `TJA1051T/3` 或经正式评审接受的等效版本；
- MCU 侧 `TXD/RXD`、逻辑电源和 GND 标识；
- 总线侧 `CANH/CANL` 标识；
- 120 Ω termination 的跳线、焊桥或开关位置；
- 逻辑电压要求不能仅凭商品标题推断，后续连接前必须用实物资料复核；
- 模块正反面无焊锡桥、裂纹或弯针。

判定：终端状态、逻辑电压或针脚方向不明确时标记 HOLD，禁止试接 NUCLEO。

#### H0-03C ARCTIC P8 PWM PST non-CO 风扇（现场核对完成；标签近照待补）

核对：

- 完整产品标签、型号、额定电压和电流；
- 为 12 V、4-wire PWM fan；
- 主 4-pin 插头方向及防呆结构；
- PST 额外串联接口单独标识，初始验证不使用；
- 扇叶、框架、线缆和插头无破损；
- 不根据黑/红/黄/蓝等线色直接认定 GND、12 V、Tach、PWM；
- 不剪原装线，后续优先改风扇延长线。

判定：完整型号、额定值或线序依据不明确时标记 HOLD。

#### H0-03D INA260 breakout（正面身份/针脚/地址焊盘照片已补；背面待补）

核对：

- 模块型号和主芯片丝印；
- `VIN+`、`VIN-` 的功率电流方向标识；
- `VCC`、`GND`、`SCL`、`SDA`、`ALERT` 针脚标识；
- 地址焊桥/跳线的到货状态；
- 端子和分流路径无明显损伤；
- H0 不连接 12 V、I2C 或 ALERT；
- 后续只按实物资料确认 3.3 V 逻辑供电和 I2C 电平。

判定：VIN 方向或逻辑针脚不清时标记 HOLD。

#### H0-03E NTC 和电阻（H0 测量完成；R10K-01 复测已归档）

核对：

- 散热器尺寸约为 100 × 80 × 20 mm；
- Heater 安装面、引线和绝缘无损伤；
- 12 V 适配器铭牌包含输入范围、输出电压、电流和极性符号；

### H0-04 无源器件阻值测量

前置条件：适配器断电，所有元件与模块完全隔离，万用表红表笔位于 `VΩ` 插孔。

测量仪表：照片可识别为 `VICTOR VC9807A+`。仪表校准状态和环境温度未记录，因此本节结论仅用于 H0 到货筛查，不构成计量校准或供应商容差认证。执行人于 2026-09-24 说明：R10K-01 初测过程中读数持续跳变，9.730 kΩ 只是 Live Photo 中抽取的一帧；该帧继续保留为无效初测证据。随后在 20 kΩ 档补充复测照片，显示 9.911 kΩ。另补充同一万用表 200 Ω 档的表笔短接照片，显示约 0.3 Ω。

测量原则：

- 记录仪表型号和档位；
- 低阻测量前先短接表笔，记录表笔/接触电阻；
- 不用手同时捏住高阻元件两端金属引脚，避免人体并联影响；
- 数值不稳定时等待稳定并记录环境；
- 不为没有数据手册容差的器件发明验收带宽。

“表笔短接”不是短接 Heater 或电源，而是在**被测对象完全断电且万用表处于电阻档**时，把红、黑两支表笔的金属尖端直接、稳定地接触在一起，用来测出表笔线、插孔和接触本身带来的串联电阻。操作顺序：

1. 黑表笔置于 `COM`、红表笔置于 `VΩ`，选择与 Heater 测量相同的电阻档；
2. 两表笔金属尖端直接接触，保持不动，等待读数稳定并记录为 `R_lead`；
3. 分开表笔，再以相同档位和相近接触力度测量 Heater，记录显示值 `R_display`；
4. 形成近似修正值 `R_heater = R_display - R_lead`，同时保留两个原始读数；
5. 如果表笔互相接触时读数仍明显跳变，先检查探针氧化、插头松动、量程和电池，不继续给 Heater 下结论。

## 10. Gate H0 通过条件

仅当以下条件全部满足时，Gate H0 判定为 PASS：

1. 设备身份、数量和基本电气信息明确；
2. 每件关键硬件都有独立、可追溯的照片证据；
3. 必需的无源阻值、适配器空载电压和极性均已记录；
4. 没有未处置的关键错件、损伤、极性或接口不确定性；
5. 未进行复杂连接和完整功率上电；
6. H1 所需的两块 NUCLEO 均具备独立 USB 检查条件；
7. 记录内容真实，不把未测量项目描述为实测，不把推断描述为事实。

若非关键辅材缺失但不影响 H1，可将 Gate H0 判为“有条件通过”，但必须保留偏差 ID、补齐日期和对后续 Gate 的明确限制。关键板卡、适配器极性、模块身份或安全状态不明确时不得有条件通过。

## 11. H1 准入和仍然禁止的动作

Gate H0 PASS 或 CONDITIONAL PASS 只授权进入 H1 的最小动作：

1. 选择一块已验收的 NUCLEO；
2. 仅通过 USB 给该单板供电；
3. 不连接 12 V、Fan、Heater、CAN Pal、INA260 或 NTC；
4. 验证 Windows 枚举、ST-LINK、虚拟串口、CubeProgrammer 连接和目标器件信息；
5. 完成后断开，再对第二块板独立重复；
6. 一块成功不得外推另一块成功。

即使 Gate H0 PASS 或 CONDITIONAL PASS，仍不授权：

- 完整双节点 CAN；
- 风扇 12 V + PWM 联调；
- Heater 通电；
- INA260 高边功率接线；
- Thermal Plant 闭环；
- Fault 的真实危险刺激。

## 12. 常见不成熟思路及反驳

### 12.1 “先全部接起来，哪里不工作再查”

错误原因：同时引入电源、极性、线序、终端、模块版本和软件状态等多个未知量，既增加损坏风险，也破坏故障隔离。正确方法是按 Gate 逐步增加一个变量，并保留上一阶段可回退状态。

### 12.2 “两个板是同款，只验一块即可”

错误原因：同型号不代表同批次、同 PCB revision、同跳线状态或无个体损伤。双 ECU 项目最终依赖两块独立硬件，两块板必须分别建立身份和运行证据。

### 12.3 “线色很常见，照颜色接就行”

错误原因：不同厂家和转接线可能使用不同线序，PST 还增加额外接口。必须依据实物插头方向、标签和可靠资料确认，不能用颜色替代引脚定义。

### 12.4 “NTC 室温约 10 kΩ，所以已经证明它是 B3950”

错误原因：单点阻值只能支持标称阻值核对，不能唯一确定 B 值。B3950 需要采购资料或多温点测量支持。

### 12.5 “终端跳线看起来插上了，所以一定是 120 Ω”

错误原因：跳线位置、焊桥版本和板上并联路径都可能影响结果。必须记录配置，并在断电状态结合阻值和模块资料核对。

### 12.6 “万用表蜂鸣说明线路正确”

错误原因：蜂鸣只表示阻抗低于仪表阈值，不能证明阻值正确、极性正确、没有错误并联或能安全承载电流。

### 12.7 “缺少示波器，所以删掉时序、Fault 或 Recovery”

错误原因：低仪器依赖只改变证据获取方式。串口日志、计数器、Debugger、GPIO、软件注入和万用表可承担主线验证；可选仪器用于增强证据，不能改变冻结功能范围。

### 12.8 “空载 12 V 正常，所以适配器和整套功率回路都没问题”

错误原因：空载测量不能证明带载能力、纹波、瞬态、接线端子、公共地或 Heater 路径合格。它只完成 H0 的基本身份和极性检查。
