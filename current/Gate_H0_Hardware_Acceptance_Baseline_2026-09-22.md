### 2.1 不允许在 Gate H0 修改的内容

- Node A / Node B 的职责边界；
- `INIT / NORMAL / DEGRADED / SAFE` 系统模式集合和综合重算原则；
- FA-01～FA-07、FB-01～FB-04、FB-06 的 Fault 范围；
- FB-05 仅作为 Fault Propagation / Aggregation 历史编号的结论；

- Diagnostic event、Freeze Frame、NVM、aging、clear 和 PC/UDS exposure；
- 需要实物或数据手册确认的模块电气细节。

禁止为了让表格“看起来完整”而编造这些数值。

## 3. Gate H0 的目的和边界

Gate H0 只回答以下问题：

1. 实际收到了什么；
2. 数量、型号、芯片、板卡版本和接口标识是否明确；
3. 是否存在缺件、错件、损伤、弯针、虚焊或不明跳线状态；
4. 无源器件基本阻值是否有记录；
5. 12 V 适配器的铭牌、空载输出和极性是否明确；
6. 是否具备进入 Gate H1 单块 NUCLEO USB Bring-up 的条件。

Gate H0 不验证：

- 固件是否能下载或运行；
- ST-LINK、虚拟串口或目标 MCU 是否能被软件连接；
- CAN 双向通信；
- 风扇 PWM、Tach、INA260、NTC 温度换算；
- FreeRTOS 调度、IPC、Fault、Fallback 或 Recovery；
- 完整 12 V 功率回路和 Thermal Plant。

这些内容分别属于 H1 及后续 Gate。不得用 H0 的照片或万用表读数替代后续运行证据。

## 4. 状态定义

| 状态 | 定义 | 处理 |
|---|---|---|
| PASS | 实物身份、数量、接口和要求的证据均明确，未发现阻止下一阶段的问题 | 可计入 H0 完成项 |
| HOLD | 信息不明确、规格不一致、针脚/极性不清、证据不足或需要数据手册复核 | 隔离该物料，不上电、不接线 |
| FAIL | 已确认错件、损坏、极性错误、输出异常或不满足基线 | 停止使用，记录并安排退换/替代评审 |
| N/A | 经本文件或上游基线确认该检查对该物料不适用 | 写明理由，不能留空代替 N/A |
| NOT CHECKED | 尚未执行 | Gate H0 关闭时不得残留关键 NOT CHECKED 项 |

一件关键物料出现 HOLD 或 FAIL，不允许通过“先接起来看看”消除不确定性。应先补证据、查资料或更换物料。

## 5. Gate H0 安全红线

### 5.1 H0 第一步的安全状态

- 12 V 适配器不接市电；
- 两块 NUCLEO 不接 USB；
- 所有模块互相分离；
- Heater、Fan、INA260、CAN Pal、NTC 均不与 MCU 连接；
- 桌面干燥、绝缘、无散落金属；
- 不佩戴可能造成短路的金属物接触裸露端子；
- 先释放人体静电，再接触开发板和模块边缘。

### 5.2 H0 全程禁止事项

- 不搭建完整 12 V 风扇或 Heater 功率回路；
- 不把 12 V 接入 NUCLEO 的 3.3 V、5 V 或 GPIO；
- 不通过面包板、细杜邦线承载 Heater 电流；
- 不启用 INA260 ALERT；
- 不连接完整双节点 CAN 网络；
- 不同时接入 CAN、风扇、传感器和 RTOS 业务固件；
- 不用真实短路、危险堵转、过压或大电流制造 Fault；
- 不剪 P8 原装线，不使用 PST 串联接口参与初始验证；
- 不根据线色、商品图片或个人经验猜测针脚；
- 不在带电对象上使用电阻档、通断档或二极管档。

### 5.3 万用表使用要求

- 黑表笔插 `COM`；
- 测电阻时红表笔插 `VΩ`；
- 测适配器电压时红表笔仍插 `VΩ`，档位设为直流电压；
- 本阶段不把表笔插入 `A` 或 `mA` 电流插孔；
- 每次改变档位前确认被测对象是否带电；
- 测电阻前确认元件与所有电源、模块和电容性电路隔离；
- 不用蜂鸣器响声代替阻值、极性或绝缘结论。

## 7. 标识和证据命名规则

### 7.1 实物 ID

先按物理身份编号，不要提前绑定软件角色：

- `NUCLEO-01`、`NUCLEO-02`；
- `CANPAL-01`、`CANPAL-02`；
- `FAN-01`；
- `INA260-01`；
- `NTC-01`；
- `R10K-01`、`R4K7-01`；
- `HEATER-01`、`HEATSINK-01`；
- `PSU12V-01`；
- 其他辅材按类型连续编号。

两块 NUCLEO 在 H1 分别验证前，不永久指定为 Node A 或 Node B。否则一旦板卡互换，照片、日志和故障定位会失去可追溯性。

### 7.2 照片命名

推荐格式：

`H0_<实物ID>_<视图>_<YYYYMMDD>_<序号>.jpg`

视图建议使用：

- `overview`：全体物料总览；
- `front`：正面；
- `back`：背面；
- `marking`：型号/芯片丝印；
- `connector`：接口及针脚标识；
- `jumper`：跳线、焊桥、DIP 或终端状态；
- `damage`：损伤或异常细节；
- `measurement`：必要的仪表读数与被测对象同框照片。

同型号的两块板必须分别拍摄，不能用其中一块代表另一块。照片应能同时看清实物 ID 标签和被核对的标识。

## 9. 执行流程

必须按 H0-01 至 H0-07 顺序执行。任何 STOP 条件出现时，停止该物料的后续步骤，但可以继续清点其他保持隔离的物料。

### H0-01 建立全断电工作状态

操作：

1. 拔除 12 V 适配器市电输入；
2. 拔除两块 NUCLEO 的 USB；
3. 拆除所有临时连接；
4. 将物料分类摆放且互不接触；
5. 放置实物 ID 标签；
6. 拍摄一张全体物料总览照。

证据：

- 总览照片编号：`________________`；
- 执行日期/时间：`________________`；
- 执行人：`________________`。

通过条件：所有物料可独立识别，现场无带电连接和复杂线束。

STOP 条件：无法确认适配器是否断电、桌面潮湿、存在裸露带电端子或金属杂物。

### H0-02 逐件清点和外观检查

每件物料至少记录：

- 实物 ID；
- 购买名称；
- 实收数量；
- 正面/背面完整丝印；
- 主芯片型号；
- PCB/板卡版本；
- 接口和针脚标签；
- 跳线、焊桥、DIP、终端电阻配置；
- 弯针、裂纹、烧痕、腐蚀、缺件、松动、虚焊嫌疑；
- 包装或铭牌异常；
- 对应照片编号；

### H0-03 关键硬件身份核对

#### H0-03A NUCLEO-F103RB ×2

逐块核对：

- PCB 正面型号包含 `NUCLEO-F103RB`；
- 目标 MCU 丝印可辨识并与 `STM32F103RBT6` 基线一致；
- 板载 ST-LINK 区域和目标板区域无明显损伤；
- USB 接口无松动、变形或异物；
- Morpho/Arduino 排针无严重弯折和短接；
- 所有出厂跳线、焊桥状态逐块拍照记录，H0 不随意改动；
- 两块板分别记录 PCB revision/版本信息；
- 不因一块板外观正常而外推另一块也正常。

判定：型号、MCU 或板版本无法确认时标记 HOLD；明显错件或损伤标记 FAIL。

#### H0-03B CAN Pal ×2

逐块核对：

- 模块产品标识和版本；
- 收发器芯片丝印是否为预期的 `TJA1051T/3` 或经正式评审接受的等效版本；
- MCU 侧 `TXD/RXD`、逻辑电源和 GND 标识；
- 总线侧 `CANH/CANL` 标识；
- 120 Ω termination 的跳线、焊桥或开关位置；
- 逻辑电压要求不能仅凭商品标题推断，后续连接前必须用实物资料复核；
- 模块正反面无焊锡桥、裂纹或弯针。

判定：终端状态、逻辑电压或针脚方向不明确时标记 HOLD，禁止试接 NUCLEO。

#### H0-03C ARCTIC P8 PWM PST non-CO 风扇

核对：

- 完整产品标签、型号、额定电压和电流；
- 为 12 V、4-wire PWM fan；
- 主 4-pin 插头方向及防呆结构；
- PST 额外串联接口单独标识，初始验证不使用；
- 扇叶、框架、线缆和插头无破损；
- 不根据黑/红/黄/蓝等线色直接认定 GND、12 V、Tach、PWM；
- 不剪原装线，后续优先改风扇延长线。

判定：完整型号、额定值或线序依据不明确时标记 HOLD。

#### H0-03D INA260 breakout

核对：

- 模块型号和主芯片丝印；
- `VIN+`、`VIN-` 的功率电流方向标识；
- `VCC`、`GND`、`SCL`、`SDA`、`ALERT` 针脚标识；
- 地址焊桥/跳线的到货状态；
- 端子和分流路径无明显损伤；
- H0 不连接 12 V、I2C 或 ALERT；
- 后续只按实物资料确认 3.3 V 逻辑供电和 I2C 电平。

判定：VIN 方向或逻辑针脚不清时标记 HOLD。

#### H0-03E NTC 和电阻

核对：

- NTC 的采购规格为 10 kΩ、B3950；
- 10 kΩ 分压电阻的标称值和容差；
- 4.7 kΩ Tach 上拉电阻的标称值和容差；
- 引脚、绝缘和封装无损伤。

注意：室温下测得约 10 kΩ 只能支持 NTC 的标称阻值核对，不能单凭一个阻值证明 B 值一定是 3950。B 值需要采购资料或多温点测量支持。

#### H0-03F Heater、散热器和适配器

核对：

- Heater 铭牌/丝印为 10 Ω / 25 W；
- 散热器尺寸约为 100 × 80 × 20 mm；
- Heater 安装面、引线和绝缘无损伤；
- 12 V 适配器铭牌包含输入范围、输出电压、电流和极性符号；
- DC 插头尺寸与 5.5 × 2.1 mm 采购基线一致；
- 适配器外壳、电缆和插头无开裂、挤压或裸铜；
- H0 不把 Heater 安装并通电，不测试温升。

### H0-04 无源器件阻值测量

前置条件：适配器断电，所有元件与模块完全隔离，万用表红表笔位于 `VΩ` 插孔。

测量原则：

- 记录仪表型号和档位；
- 低阻测量前先短接表笔，记录表笔/接触电阻；
- 不用手同时捏住高阻元件两端金属引脚，避免人体并联影响；
- 数值不稳定时等待稳定并记录环境；
- 不为没有数据手册容差的器件发明验收带宽。

| M-01 | NTC-01 | 10 kΩ @ 25°C | 采购规格 |  | N/A |  | 温度偏离 25°C 时阻值会变化 | NOT CHECKED |
| M-02 | R10K-01 | 10 kΩ | ±1% |  | N/A |  |  | NOT CHECKED |
| M-03 | R4K7-01 | 4.7 kΩ | 按实物色环/采购规格 |  | N/A |  |  | NOT CHECKED |
| M-04 | HEATER-01 | 10 Ω | 按实物/采购规格 |  |  |  | 低阻应考虑表笔电阻 | NOT CHECKED |
| M-05 | CANPAL-01 termination | 120 Ω（若启用） | 模块资料/配置 |  |  |  | 板上并联路径可能影响读数 | NOT CHECKED |
| M-06 | CANPAL-02 termination | 120 Ω（若启用） | 模块资料/配置 |  |  |  | 板上并联路径可能影响读数 | NOT CHECKED |

判定说明：

- `R10K-01` 若明确为 ±1%，独立测量应与该容差一致，同时考虑万用表精度；
- NTC 阻值必须结合温度解释，不能机械套用固定 ±1%；
- Heater 低阻测量必须扣除或说明表笔/接触电阻；
- CAN Pal 板上测得的阻值可能受到其他电路影响，需结合 termination 配置和模块原理图解释；
- 通断档只说明阻抗低到触发蜂鸣，不能代替具体阻值结论。

STOP 条件：被测对象仍与电源或其他模块连接、表笔位于电流插孔、无法确认量程或读数明显异常。

### H0-05 适配器铭牌、空载电压和极性

此步骤必须在完成外观检查后单独执行。适配器输出端不得连接 NUCLEO、Fan、Heater、INA260、面包板或其他模块。

操作：

1. 抄录 `PSU12V-01` 的完整输入、输出、电流和极性符号；
2. 确认万用表黑表笔在 `COM`、红表笔在 `VΩ`；
3. 选择直流电压档，量程高于 12 V；
4. 保持 DC 插头独立，不让表笔互相短接；
5. 按铭牌极性符号先放置表笔，再短时间接通市电；
6. 记录电压的正负号、数值和稳定性；
7. 交换表笔只用于必要的极性确认，不允许表笔桥接中心针与外壳；
8. 测量结束后先断开市电，再收起表笔和适配器；
9. 拍摄适配器铭牌及必要的测量证据照片。

- 实测极性必须与铭牌和计划连接方式一致；
- 实测输出应与适配器制造商规格一致；
- 如果只有“12 V”铭牌而没有公开空载容差，记录实际值，不擅自编造 ±X% 的产品合格标准；

## 10. Gate H0 通过条件

仅当以下条件全部满足时，Gate H0 判定为 PASS：

1. 设备身份、数量和基本电气信息明确；
2. 每件关键硬件都有独立、可追溯的照片证据；
3. 必需的无源阻值、适配器空载电压和极性均已记录；
4. 没有未处置的关键错件、损伤、极性或接口不确定性；
5. 未进行复杂连接和完整功率上电；
6. H1 所需的两块 NUCLEO 均具备独立 USB 检查条件；
7. 记录内容真实，不把未测量项目描述为实测，不把推断描述为事实。

若非关键辅材缺失但不影响 H1，可将 Gate H0 判为“有条件通过”，但必须保留偏差 ID、补齐日期和对后续 Gate 的明确限制。关键板卡、适配器极性、模块身份或安全状态不明确时不得有条件通过。

## 11. H1 准入和仍然禁止的动作

Gate H0 PASS 只授权进入 H1 的最小动作：

1. 选择一块已验收的 NUCLEO；
2. 仅通过 USB 给该单板供电；
3. 不连接 12 V、Fan、Heater、CAN Pal、INA260 或 NTC；
4. 验证 Windows 枚举、ST-LINK、虚拟串口、CubeProgrammer 连接和目标器件信息；
5. 完成后断开，再对第二块板独立重复；
6. 一块成功不得外推另一块成功。

即使 Gate H0 PASS，仍不授权：

- 完整双节点 CAN；
- 风扇 12 V + PWM 联调；
- Heater 通电；
- INA260 高边功率接线；
- Thermal Plant 闭环；
- Fault 的真实危险刺激。

## 12. 常见不成熟思路及反驳

### 12.1 “先全部接起来，哪里不工作再查”

错误原因：同时引入电源、极性、线序、终端、模块版本和软件状态等多个未知量，既增加损坏风险，也破坏故障隔离。正确方法是按 Gate 逐步增加一个变量，并保留上一阶段可回退状态。

### 12.2 “两个板是同款，只验一块即可”

错误原因：同型号不代表同批次、同 PCB revision、同跳线状态或无个体损伤。双 ECU 项目最终依赖两块独立硬件，两块板必须分别建立身份和运行证据。

### 12.3 “线色很常见，照颜色接就行”

错误原因：不同厂家和转接线可能使用不同线序，PST 还增加额外接口。必须依据实物插头方向、标签和可靠资料确认，不能用颜色替代引脚定义。

### 12.4 “NTC 室温约 10 kΩ，所以已经证明它是 B3950”

错误原因：单点阻值只能支持标称阻值核对，不能唯一确定 B 值。B3950 需要采购资料或多温点测量支持。

### 12.5 “终端跳线看起来插上了，所以一定是 120 Ω”

错误原因：跳线位置、焊桥版本和板上并联路径都可能影响结果。必须记录配置，并在断电状态结合阻值和模块资料核对。

### 12.6 “万用表蜂鸣说明线路正确”

错误原因：蜂鸣只表示阻抗低于仪表阈值，不能证明阻值正确、极性正确、没有错误并联或能安全承载电流。

### 12.7 “缺少示波器，所以删掉时序、Fault 或 Recovery”

错误原因：低仪器依赖只改变证据获取方式。串口日志、计数器、Debugger、GPIO、软件注入和万用表可承担主线验证；可选仪器用于增强证据，不能改变冻结功能范围。

### 12.8 “空载 12 V 正常，所以适配器和整套功率回路都没问题”

错误原因：空载测量不能证明带载能力、纹波、瞬态、接线端子、公共地或 Heater 路径合格。它只完成 H0 的基本身份和极性检查。
