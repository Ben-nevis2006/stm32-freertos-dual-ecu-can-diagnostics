# Gate H2 CAN Bring-up 排障证据复盘（2026-10-02～2026-10-07）

> 本文按真实时间顺序复盘统一推送前累计的 H2 工作。它保留失败、误判修正和证据边界，不把最终通过改写成“一次点亮”。项目阶段属于**原型/技术验证**，不是生产落地。

## 1. 问题背景

目标是在不接入任何 12 V 功率外设的前提下，让两块 STM32F103 NUCLEO 通过两块 TJA1051T/3 CAN Pal 建立 `500 kbit/s` 双向 CAN 链路，并形成能审计的 Gate H2 证据。

现场限制包括：

- 只有两路电脑 USB，板卡身份、COM 号和物理端口不能混为一谈；
- CAN Pal 排针由用户手工焊接，端子、焊点、跳线和 SLNT 都可能引入独立故障；
- 单人同时持表笔和手机容易牵动探针/USB/跳线，曾出现 ST-LINK `LD1/COM` 红闪和 Windows 重枚举；
- 初始最小固件能运行 UART/RTOS，但 CAN 两侧均只有 3 个邮箱入队后堵塞、接收始终为 0；
- 最终不仅要“有波形”，还要满足正式 ID/DLC/payload、AliveCounter、错误状态和断线恢复门槛。

## 2. 方案决策

采用“安全边界先行、单变量分层、失败证据保留”的排障策略：

1. **先无源后有源**：先查 Vcc-GND 非短路和 H-L 终端阻值，再 USB 上电，始终隔离 12 V/负载。
2. **身份固定**：按板号和 ST-LINK 设备身份区分 Node A/B，不依赖可能变化的 COM 号或电脑 USB 口。
3. **从 MCU 到总线逐层测量**：`PA12/TX → SLNT → CANH/CANL → RX → UART 计数器`，不靠反复盲换线猜测。
4. **先固定帧、后正式帧**：先用 `0x321/0x322` 隔离物理链路，再切换到 `0x100/DLC2` 与 `0x180/DLC5`。
5. **时钟改为可重复基准**：从 HSI 派生时钟切换到 ST-LINK 8 MHz MCO 的 HSE bypass，保留相同 `500 kbit/s / 87.5%` 位时序。
6. **以计数器而非“看起来正常”验收**：同时检查 `tx/rx`、四项错误、TEC/REC、EWGF/EPVF/BOFF 和末态 ESR。
7. **主动注入故障**：正式基线通过后受控断开 H/L，要求故障必须被观察；恢复后重新跑完整窗口，不能只凭重新连上就关闭 Gate。

没有采用的做法包括：未在故障未清时接入 12 V 或负载；未把 ST-LINK 通信灯当成 CAN 状态灯；未用照片代替连续性/运行日志；未删除失败记录来美化结果。

## 6. 效果证据

### 6.1 现象—验证—结论链

| 日期/阶段 | 现象 | 单变量验证与结果 | 结论性质 |
|---|---|---|---|
| 10-03～10-05 初始接线 | CAN 邮箱 3 帧后堵塞、双侧 `rx=0` | 复核发现 Node A TX/RX 对调；修正后故障仍在 | **实测排除**：线序是一个错误，但不是唯一根因 |
| 10-04 USB 扰动 | `LD1/COM` 由黄/橙转红闪，并伴随 Windows 断连/重连 | 移除表笔和机械扰动后静置 2 min 稳定 | **实测边界**：事件是 ST-LINK/USB 重枚举，不是 CAN 状态；具体瞬态路径未唯一定位 |
| 10-07 SLNT/总线电平 | SLNT 悬空约 2.2 V；Node B 下拉后 H/L 出现相反趋势，Node A 仍异常 | 明确把 SLNT 接 GND；后续发现 Node B SLNT 接触曾断开，重新固定后错误计数显著恢复 | **实测根因之一**：SLNT 不能悬空，接触不稳可造成静默/高错误状态 |
| 10-07 CANPAL-01 | Node A 下拉 SLNT 后 CANH 约 1.25 V、CANL 约 0.06 V；termination ON 时对地约 60.6 Ω | 用户检查发现终端网络附近焊锡碰邻近贴片位置，清理后 ON 状态不再呈异常对地低阻，H/L 回到约 3.3/1.8～2.0 V 活动范围 | **用户现场实测根因之一**：焊锡桥连干扰了终端/分裂网络；无显微截面，精确桥接节点不扩张推断 |
| 10-07 Node B RX | 局部交换/重启后节点行为不一致 | 更换 RX 跳线并重启后启动/接收路径恢复 | **用户现场实测根因之一**：旧 RX 跳线存在开路或间歇接触 |
| 10-07 时钟 | 线序和局部硬件修复后仍需消除双节点振荡器容差风险 | 两端统一为 HSE bypass 8 MHz、PLL×8；重新构建/刷写 | **工程修正**：消除 HSI 不确定性；因与其他修复相邻，不把它单独宣称为唯一故障根因 |
| 10-07 固定帧 | 修复前虽能收发，但 TEC/REC 高且偶发 seq_err | 修复 Node B SLNT 接触后连续 3×80 s：双方每轮约 690 帧，四项错误全 0，无 Warning/Passive/Bus-off | **实测通过**：物理链路具备可重复双向收发 |
| 10-07 正式帧 | 需要证明不是只为测试帧“特调” | `0x100/DLC2` 与 `0x180/DLC5` 运行 80 s；A=`687/688`、B=`690/689`，四项错误全 0 | **实测通过**：ID/DLC/payload/AliveCounter 基线成立 |
| 10-07 故障注入 | 断开 H/L 后双方停止接收 | A tx_fail=194；B tx_fail=187 且出现 Bus-off 样本 | **实测通过**：物理断线能被明确观察 |
| 10-07 首次恢复 | 重新接线后虽然收发恢复，A max TEC 仍 252，第二轮仍 208 | 两轮均判 FAIL；断电后从两端测得 60.3/60.4 Ω，并重新检查接线接触 | **阶段失败保留**：直流终端正确不等于动态接触已可靠；未唯一定位到某一插头 |
| 10-07 最终恢复 | 接触复核后重启 | 30 s 预检通过；80 s 最终 A=`687/688`、B=`690/689`，四项错误全 0，max TEC/REC 均 `6/0`，末态 ESR=0 | **实测最终通过** |

### 6.2 可核验量化结果

- 两端 termination 并联：早期 `60.41 Ω`；最终恢复前分别 `60.3 Ω`、`60.4 Ω`。
- 固定帧：连续 3 轮 `80 s`，Node A 每轮约 `687/688`、Node B 约 `690/689`，四项错误均 0。
- 正式帧基线：`80 s`，A/B 四项错误均 0；max TEC 分别 16/4，末态 ESR 均 0。
- 断线恢复最终窗口：`80 s`，A/B max TEC/REC 均 `6/0`，无 Warning/Passive/Bus-off 样本。
- 两份最终日志 SHA-256：Node A `9B06682C…BB313`；Node B `5B908CAF…B493E`。

- 用户负责实体焊接、接线、测量、示波器操作、断电/上电和现场异常识别；Codex 没有直接接触硬件。

- “CANPAL-01 焊锡桥连”“Node B RX 跳线”“Node B SLNT 接触”有现场动作与前后对比支持；恢复阶段的具体接触点没有被仪器唯一定位，不能写成已精确锁定某一个端子。
- 时钟改造提升了可重复性并消除了 HSI 风险，但现有材料不足以把全部早期故障单独归因于 HSI。
- 本项目当前不能宣称生产落地、整车验证或功能安全合规。
